# حساب سرمایه‌گذاران — پایش سهم بر پایهٔ وزن شمش آلومینیوم

## ۱. ایدهٔ محوری
واحد حسابداری = **کیلوگرم شمش آلومینیوم**، نه ریال.

هر تراکنش پولی در لحظهٔ ثبت با قیمت همان لحظه به وزن تبدیل می‌شود:

```
weight_kg = amount_rial / price_rial_per_kg
```

- واریز (`IN`)  → وزن مثبت
- برداشت (`OUT`) → وزن منفی

موجودی وزنی هر شریک = جمع جبری وزن تراکنش‌های او.
قیمت بعداً هر چه شود، **وزن ثابت می‌ماند** — این دقیقاً همان چیزی است که می‌خواهیم.

## ۲. فرمول‌ها

| کمیت | فرمول |
|---|---|
| وزن شریک i | `W_i = Σ (±amount / price)` |
| وزن کل | `W_total = Σ W_i` |
| درصد سهم شریک i | `S_i = W_i / W_total × 100` |
| ارزش روز شریک i | `V_i = W_i × price_now` |
| خالص نقدی شریک i | `C_i = Σ (+in) − Σ (−out)` |
| سود/زیان شریک i | `P_i = V_i − C_i` |
| بازده شریک i | `P_i / Σ(in) × 100` |

**نکتهٔ مهم:** درصد سهم یک کمیت *مشتق‌شده* است، نه ذخیره‌شده. هرگز آن را در دیتابیس ننویسیم — همیشه از روی وزن‌ها محاسبه شود، وگرنه ناسازگاری پیش می‌آید.

## ۳. تصمیم‌های ظریف (نیاز به تأیید شما)

1. **برداشت بیش از موجودی:** پیش‌فرض = هشدار می‌دهد ولی اجازه می‌دهد (وزن منفی ممکن است). گزینهٔ دیگر: مسدود کردن.
2. **ویرایش/حذف تراکنش:** پیش‌فرض = «حذف نرم» (soft delete) با نگه‌داشتن رد ممیزی. تراکنش پاک نمی‌شود، فقط `voided_at` می‌خورد.
3. **قیمت جاری برای داشبورد:** آخرین قیمت ثبت‌شده در جدول قیمت‌ها (که می‌توان بدون تراکنش هم قیمت ثبت کرد، صرفاً برای به‌روز کردن ارزش‌گذاری).
4. **دقت اعداد:** مبلغ ریالی `numeric(20,0)`، قیمت `numeric(20,2)`، وزن `numeric(20,6)` (تا میلی‌گرم). هرگز float نه.

## ۵. صفحات نرم‌افزار
1. **داشبورد** — کارت هر شریک (وزن، درصد، ارزش، سود/زیان)، نمودار دایره‌ای سهم، نمودار خطی رشد وزن، قیمت جاری.
2. **ثبت تراکنش** — فرم سریع با پیش‌نمایش زندهٔ «این مبلغ = چند کیلوگرم».
3. **تراکنش‌ها** — جدول، فیلتر بر اساس شریک/نوع/بازهٔ تاریخ، حذف نرم، خروجی اکسل.
4. **قیمت‌ها** — ثبت و تاریخچهٔ قیمت شمش.
5. **شرکا** — افزودن/ویرایش شریک.
6. **ورود** — Supabase Auth (فعلاً فقط مدیر).
